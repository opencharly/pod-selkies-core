A published tag embeds the pins it carried **at mint time**, and this repo's tag is what

release, so a closure pinning this repo alongside anything that resolves the newer pixelflux gets
two versions of it — and a `resolved to multiple versions` warning it **cannot clear from its own

## This is opened predictively, and that is deliberate

The consuming closure does **not** report this conflict yet. The repo that pins
`pod-selkies-core` has only just advanced to `v2026.243.1811` — the tag that carries this stale
pixelflux pin — so the next resolve is where it would surface.

So it is fixed before it lands rather than rediscovered in another round.

**This is the shape of the campaign's tail.** Repairing a candy at its source re-tags that repo,
which makes every consumer's pin of it stale in turn — including pins written by earlier waves of
this same campaign. `layer-wl-record-pixelflux@v2026.243.1823` is itself a tag produced by this
campaign two waves ago. The graph is repaired leaves-first with the closure re-measured between
waves; where the next conflict is derivable from the tags, it is opened ahead of the measurement
instead of after it.

## The candy's own `version:` is deliberately NOT bumped

`PickCandyVersion` (`sdk/loaderkit/candy_version.go`) warns only when two materializations of a
bare ref carry **different per-entity `version:` values**; identical entity versions across
different git tags resolve silently on tag freshness. Bumping the stamp for a pin-only change
would manufacture the exact warning this PR removes, for every consumer still pinning an older tag
of this repo.

## Rulebook compliance

- **R1 (RCA)** — the conflict is derived from the tag graph rather than waited for; the mechanism
  (arbiter compares per-entity `version:`; tags freeze their pins at mint time) is stated and was
  verified against the resolver source.
- **R3 (no duplication)** — one pin line.
- **R4 (no workarounds)** — advanced at the source; pinning around it downstream is impossible by
  construction.
- **R5 (delete legacy)** — the stale pin is replaced.
- **R6 (git safety)** — feature branch, no force-push, no hook bypass.
